A chat request naming an agent that does not exist is answered 404 `Agent '<name>' not found` where it was 400, and `registry.agents.<id>.surfaces` now governs the chat routes as well as the catalog: an agent kept off `rest` is refused like an unknown agent on REST, thread and WebSocket chat, and a request naming no agent runs the first agent on `rest`. A chat request body can no longer carry a `surface` key of its own (422). To migrate, treat 404 as the unknown agent, add `rest` to the `surfaces` of every agent you chat with over those routes, and rename a `surface` key your clients send; see [REST API](https://kernel.yaala.ai/docs/api/rest-api).
