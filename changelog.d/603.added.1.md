Add credentials for downstream calls: with an `identity.credentials` block, each authenticated request's credential is kept, encrypted with AES-GCM, in a credential store (`in_memory`, `redis`, `valkey` or `dynamodb`) until its run ends, and a tool gets a token for a downstream service with `ToolContext.get().credentials.token_for(audience)`. Only the development `passthrough` exchanger ships; bring a `TokenExchanger` of your own by dotted path. The AWS Lambda and ECS WebSocket deployments keep no credential yet. See [Credentials for downstream calls](https://kernel.yaala.ai/docs/advanced/identity-and-access#credentials-for-downstream-calls).
