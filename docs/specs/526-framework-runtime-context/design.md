# #526: Pass a per-run framework context/state through the Session to every framework adapter

Give application code a framework-agnostic way to carry a **context/state object** across turns of a conversation: persist it in the `Session` under a reserved key, inject it into the underlying framework when the agent runs, and write the (possibly mutated) object back to the same key after the run. Each of the six framework adapters maps this one AK-level object onto its own native context/state mechanism, and callers reach it through dedicated `Session` accessor methods rather than the raw key.

## Motivation

- Every framework accepts caller-supplied context/state, but AK threads none of it through today — each runner sets up only the AK-internal `ToolContext` contextvar and never passes a native context object into the framework call:
  - OpenAI: `Runner.run(agent.agent, input_data, session=session_to_use)` — no `context=` argument (`ak-py/src/agentkernel/framework/openai/openai.py:183`).
  - LangGraph: `agent.agent.ainvoke(input={"messages": messages}, config=config)` — `config` only carries `thread_id`; no caller state merged in (`ak-py/src/agentkernel/framework/langgraph/langgraph.py:390`, config built at `:353`).
  - CrewAI: `crew.kickoff_async(inputs={})` — inputs are hard-coded empty (`ak-py/src/agentkernel/framework/crewai/crewai.py:378`).
  - Google ADK: session state is seeded only with the internal `ak_tool_context` id (`ak-py/src/agentkernel/framework/adk/adk.py:162`).
  - Smolagents: `agent.agent.run(prompt, reset=False)` — no `additional_args` (`ak-py/src/agentkernel/framework/smolagents/smolagents.py:157`).
  - Pydantic AI: `agent.agent.run(content, message_history=history)` / `agent.agent.run_stream(content, message_history=history)` — no `deps=` argument, so every AK-run Pydantic AI agent gets the `deps=None` default (`ak-py/src/agentkernel/framework/pydanticai/pydanticai.py:149`, `:189`).
- The `Session` already stores per-framework state under a framework-name key (`session.get(FRAMEWORK) or session.set(FRAMEWORK, ...)`) — e.g. `openai.py:95`, `langgraph.py:326`, `crewai.py:316`, `pydanticai.py:84`, so a caller-facing context key fits the existing key/value model on `Session` (`get`/`set`, `ak-py/src/agentkernel/core/base.py:142`, `:178`).
- `Session` already fronts its other reserved keys with named accessors — `get_volatile_cache()` / `get_non_volatile_cache()` (`base.py:164`, `:171`) — so callers never spell `Session.Keys.VOLATILE_CACHE.value`. The context key should follow the same shape instead of pushing the enum lookup onto every caller.
- Durable session keys already survive across turns: `Runtime.run()` calls `self.sessions().store(session)` after post-hooks (`ak-py/src/agentkernel/core/runtime.py:218`), and `store()` persists every non-volatile top-level key (`Session.get_all`, `base.py:135`). A new top-level key is persisted with no extra plumbing.
- Session values are serialized with `pickle` (`BinarySerde.dumps/loads`, `ak-py/src/agentkernel/core/session/serde.py:24`,`:36`), so any context object must be picklable — this constrains what a caller may put in it.
- Hooks can already read and mutate the session (`PreHook.on_run(session, ...)` / `PostHook.on_run(session, ...)`, `ak-py/src/agentkernel/core/hooks.py:21`,`:51`), but a hook **cannot** inject the object into the native framework call — only the runner, which owns the `Runner.run`/`ainvoke`/`kickoff_async` invocation, can. This splits the responsibilities cleanly and is the basis for the surface below: **hooks own seed/read of the context, the runner owns injection and write-back, and tools use the framework-native handle** — no third party needs the reserved key.

## Requirements

### Core

- Reserve a **single** session key `framework_context` shared by all frameworks. Add it to the `Session.Keys` enum (`base.py:52`), alongside `v_cache`/`nv_cache`, rather than a bare module constant — same discoverability and one obvious home for the reserved name. *(Decision: open question 1.)*
  - **Absent key** (nothing stored) ⇒ inject nothing / framework default ⇒ **no behavior change** for existing apps.
  - A caller-set **empty dict `{}`** is treated as "present but empty": it is injected and round-tripped, so a pre-hook can seed an empty context on turn 1 and have tools populate it through the native handle. Only `None`/absent means "no context". Injecting `{}` is a no-op on every framework **except smolagents**, where any non-`None` `additional_args` is also appended to the task prompt (see the smolagents note).
  - The value is a **`dict`**. *(Decision: open question 4.)*
- **Scope: all six adapters**, including **Pydantic AI** — its `deps=` slot is currently never passed (every AK-run Pydantic AI agent silently gets `deps=None`), so injecting the context there is part of this change, not a follow-up. Five of the six gain injection + write-back (OpenAI, Pydantic AI, smolagents, Google ADK, LangGraph); CrewAI is explicitly unsupported (warn and skip). Traced subclasses must inherit the plumbing rather than re-implement the native call — see "Traced runners".
- Provide the load/write-back plumbing once, in the base `Runner`, and dedicated **accessor methods on `Session`** as the caller-facing surface — see the two subsections below.

### Caller API — dedicated `Session` accessor methods

**Requirement: callers never touch the reserved key directly.** Access goes through three dedicated methods on `Session`, mirroring the existing `get_volatile_cache()` / `get_non_volatile_cache()` shape (`base.py:164`, `:171`). *(Decision: **supersedes** the earlier "no extra surface" answer to open question 2 — review feedback.)* Nothing outside `Session` — hooks, examples, docs, or the base `Runner` itself — spells `Session.Keys.FRAMEWORK_CONTEXT.value` or reaches through `session.get(...)` / `session.set(...)` for this key:

- `get_framework_context() -> dict | None` — returns the **live stored dict**, or `None` when the key is absent. **Non-mutating: it never auto-creates the key**, because absent-vs-`{}` is a load-bearing distinction (above) and a plain read must not silently flip a session from "no context" to "present but empty".
- `set_framework_context(context: dict) -> dict` — seeds/replaces the context and returns it. **Raises `TypeError` when `context` is not a `dict`**, so a wrong-typed value fails on the caller's own line instead of mid-run inside a runner.
- `clear_framework_context() -> None` — deletes the key, returning the session to "absent" (⇒ nothing injected on the next turn). Without it, un-setting the context would still require the raw key.
- **No get-or-create flag.** Seeding is the caller's explicit two-liner (`ctx = session.get_framework_context()`, then `if ctx is None: ctx = session.set_framework_context({...})`) — a `create=`/`default=` parameter would make "does this read mutate the session?" unanswerable from the call site.
- The reserved-key type check therefore lives in **two** places: `set_framework_context` (caller-facing, fail-fast) and `_load_framework_context` (defence for a value written through the raw `session.set(...)`, which stays legal but is not the documented path).
- The base `Runner` plumbing uses these same accessors, so the raw key name appears nowhere outside `Session`.
- **Scope of the accessors: pre-hooks and post-hooks only.** *(Decision: review feedback; resolves the `ToolContext` open question as "no".)* The three `Session` methods are the surface for `PreHook.on_run(session, ...)` and `PostHook.on_run(session, ...)` (`hooks.py:21`, `:51`) — the two places AK hands application code the session around a run:
  - **Pre-hook** seeds or edits the context *before* the runner loads it, so the edit is part of the dict that gets injected this turn.
  - **Post-hook** reads (and may edit) the context *after* write-back, so it observes the completed run's mutations — and post-hooks run before `Runtime.run()` calls `store()` (`runtime.py:218`), so a post-hook edit is persisted.
  - **Tools do not go through the session for this.** A tool reads and mutates the context through its **framework-native handle** — `RunContextWrapper.context` (OpenAI), `RunContext.deps` (Pydantic AI), `agent.state` (smolagents), the ADK session `state`, LangGraph state channels — which is the whole point of injecting it. Routing tool access back through `Session` would bypass the native mechanism and, on the copy-on-load frameworks, write to a different object than the one the run is carrying.
  - **No accessor is added to `ToolContext`**, and none is needed: tools have the native handle. `ToolContext.get().session` (`core/tool.py:74`) stays reachable, so this is a **documented contract, not an enforced boundary** — nothing raises if a tool calls the accessor; it is simply not the supported path and gets none of the guarantees above.
  - **CrewAI has neither path** (no injection, no native handle) — see the CrewAI note.

### Base `Runner` plumbing

- Provide the load/write-back plumbing once, in the base `Runner` (`base.py:210`), so each adapter only implements the native mapping:
  - `_load_framework_context(session) -> dict | None` — read the reserved key **via `session.get_framework_context()`**. **Returns a deep copy**, not the live stored object (see "Load semantics" below).
  - `_store_framework_context(session, ctx) -> None` — merge `ctx` over the loaded context per the merge rule and write it back **via `session.set_framework_context(...)`**. The base plumbing goes through the same accessors it asks callers to use; the raw key name appears nowhere outside `Session`.
  - Two supporting helpers live in the same place, so no adapter re-implements them: a **picklability check** run on the merge result (see "Serialization") and a **stream write-back failure logger** (see "Streaming write-back failures are logged, not raised"). Four base helpers total; each adapter supplies only its injection point and its `produced` extraction.
- Runners call load before invoking the framework and write-back after the native call completes, for both `run()` and `stream()`. Placement is per-adapter, not a uniform `try`/`finally` shape: OpenAI/LangGraph/CrewAI/smolagents/Pydantic AI wrap the call in `try/except … finally: context.reset()` (Pydantic AI's `stream()` has `try … finally` with no `except`, `pydanticai.py:179,196`), but **ADK's `run()` uses `with ctx:` (`adk.py:213`) rather than a `finally: context.reset()`** — it has a `try/except` (`adk.py:206,224`) but no `finally`, so its write-back goes after the `with ctx:` block, inside the `try`. Each adapter places the `_load_/_store_` calls around its own native invocation; do not assume a shared try-body across all six.

### Load semantics — return a deep copy

- `_load_framework_context` returns a **deep copy** of the stored dict, and write-back stores the merge result. Its main purpose is **crash-isolation**: OpenAI and Pydantic AI tools mutate the injected object **in place** (through `RunContextWrapper.context` and `RunContext.deps` respectively), so if load handed out the live stored reference, the session key would already reflect partial tool mutations *before* write-back — and a mid-run crash (write-back skipped, see "Write-back") would leave the stored context half-mutated. Copying on load keeps the stored object untouched until a successful write-back replaces it wholesale.
  - Note: for OpenAI and Pydantic AI the "incoming" copy and the "post-run" object are the **same reference** (tools mutate the copy), so the shallow-merge there is effectively identity. The merge rule does real work only for frameworks whose write-back source is a *different* object than the injected one — smolagents `agent.state`, ADK session `state`, LangGraph `result` — where untouched caller keys must be preserved.
  - `get_framework_context()` hands hooks the **live** dict, not a copy — only the runner's `_load_framework_context` copies. A hook mutating the dict it got from the accessor is editing the stored context directly, which is the intended pre-hook seeding / post-hook edit ergonomic; the crash-isolation guarantee covers the *run*, not hook edits outside it.

### Write-back — always reflect the latest context

- After the run, the key is **updated with the latest context** — any mutations the framework surfaced during the run, shallow-merged over the incoming (copied) context per the merge rule in the per-framework table. *(Decision: open question 3.)*
- **On framework error, do not write back.** *(Decision.)* Every runner catches its own exceptions and returns an error reply (`openai.py:191`, `langgraph.py:399`, `crewai.py:397`, `smolagents.py:167`, `adk.py:224`), so `store()` still runs afterward (`runtime.py:218`) and persists the session — but the write-back must sit **after a successful native call, inside the `try` and before the `except`**, so a crashed or partial run is skipped and the **previously stored context is left intact** (the deep copy loaded this turn is simply never written back). A turn's context update is therefore atomic: it either fully reflects a completed run or is unchanged.
- Fidelity is per-framework (see the table), not uniform: OpenAI and Pydantic AI round-trip fully; **ADK** round-trips the whole session-scoped state minus AK-internal and ADK-scoped keys (so keys a tool *adds* survive); **smolagents** round-trips only the keys the caller pre-seeded (added keys are dropped); LangGraph round-trips only keys its state schema declares as channels *and* the caller pre-seeded; CrewAI does not support it — a set `framework_context` is refused with a warning and never injected or written back.
- **Merge rule**: the framework's post-run state is **shallow-merged over** the incoming context — top-level keys the framework touched win (last-write-wins), keys the caller seeded but the framework never touched are preserved, and nested structures are replaced wholesale by the winning side (no deep/recursive merge). *(Decision.)*
- Never overwrite the key with an empty/`None` value when no context was present or produced (a caller-set `{}` is "present" and is preserved — see Core).

### Per-framework mapping

The `framework_context` dict is **merged into** the native mechanism on input (added to, not replacing, existing native state) and the produced state is read back on output. **The six frameworks differ in how faithfully they can round-trip a caller dict** — the mapping is graded honestly below rather than presented as uniform, because the write-back fidelity is not the same everywhere and callers need to know where mutations actually survive.

| Framework | Fidelity | Inject on input (merge) | Write-back source |
|---|---|---|---|
| OpenAI | **Full round-trip** | `Runner.run(..., context=ctx)` / `Runner.run_streamed(..., context=ctx)` — tools read/write via `RunContextWrapper.context` (`openai.py:183,214`) | the same object, mutated in place by tools |
| Pydantic AI | **Full round-trip** | `agent.agent.run(content, message_history=..., deps=ctx)` / `agent.agent.run_stream(..., deps=ctx)` (`pydanticai.py:149`, `:189`) — tools and instruction functions read/write via `RunContext.deps` | the same object, mutated in place by tools |
| Smolagents | **Round-trips seeded keys only** | `agent.run(prompt, additional_args=ctx, reset=False)` (`smolagents.py:157`) — note this **also appends the context to the task prompt** (see note) | `agent.state` read after the run, **restricted to the keys the caller seeded** — `agent.state` also holds framework-internal entries that must not leak into `framework_context` |
| Google ADK | **Round-trips all caller-visible state** (incl. tool-added keys) | merge into the ADK session `state` delta alongside `ak_tool_context`, **internal key assigned last** so a caller key can never displace it (`adk.py:162`) | ADK session `state` read after the run — **not** filtered to the seeded keys, with `ak_tool_context` and ADK's `app:`/`user:`/`temp:`-scoped keys stripped (see ADK note) |
| LangGraph | **Round-trips only declared state channels** | **spread** the dict's top-level keys into the `ainvoke`/`astream_events` `input` alongside `messages` — `input={**framework_context, "messages": messages}` — `messages` written last (`langgraph.py:391,427`). The keys sit at the **top level** of the input state (so they map onto the graph's state channels), **not** nested under a `framework_context` key, and never replace `messages` | keys read back only if the graph's state schema declares them as channels **and** the caller seeded them (see LangGraph note) |
| CrewAI | **Unsupported — warn and skip** | not injected; a set `framework_context` is refused with a warning (see CrewAI note) | none; the stored key is left untouched |

On write-back the produced state is shallow-merged over the incoming (copied) context per the **Merge rule** above (framework value wins per touched top-level key; untouched caller keys preserved; no deep merge).

- **CrewAI note (unsupported — warn and skip)**: CrewAI's `kickoff(inputs=...)` are **template-interpolation variables**, not a context/state object — they `.format()`-substitute `{placeholder}` tokens in the task `description`/`expected_output` and the agent `role`/`goal`/`backstory`. Today `inputs={}` is passed (`crewai.py:378`), so interpolation is effectively skipped; passing a non-empty `inputs=ctx` would **turn interpolation on** and raise `KeyError` on any literal `{`/`}` in the (user-derived) task description built by `_describe(...)` (`crewai.py:305`). CrewAI therefore exposes **no safe caller-state slot**. **Behavior:** when a session carries a non-empty `framework_context`, the CrewAI runner does **not** inject it and logs a **single warning per runner instance** — e.g. `"framework_context is set but CrewAI does not support per-run caller context/state; ignoring it."` — via the runner's `self._log.warning(...)`. *(Decision: **not** once per run/turn. The condition holds on every turn of a session that seeded a context, and the warning is unactionable, so repeating it per turn is pure log noise; a one-shot instance flag also cannot grow unbounded the way a set of seen session ids would. A runner is per-module and long-lived, so this is effectively once per process.)* A caller-set `{}` is falsy and does **not** warn. `kickoff_async(inputs={})` stays as-is, and the stored key is left untouched (no write-back). This makes the limitation explicit at runtime rather than silently dropping the context.
  - Consequence of the hooks-only scope: on CrewAI a **tool has no supported path to per-run caller state at all** — nothing is injected, so there is no native handle, and the session accessors are a hook-only surface. CrewAI apps that need tool-visible per-run state should use the session's non-volatile cache (`Session.get_non_volatile_cache()`, `base.py:171`), which exists for exactly this "application data outside the agent context" case and is reachable from a tool via `ToolContext.get().session`.
- **ADK note**: `GoogleADKSession` uses an `InMemorySessionService` (`adk.py:53`), so ADK's native state is **not** part of the pickled AK session — write-back is what gives the context cross-turn durability (via AK's `framework_context` key), not ADK itself. The read-back scope is the whole state accumulated by the run, **not** just the seeded keys, so keys a tool adds mid-run do round-trip (the deliberate divergence from smolagents). Two classes of key must be stripped before merging:
  - `ak_tool_context` — the runner seeds it with a **fresh id every turn** (`adk.py:162`), so leaving it in would make the caller's dict accumulate a stale internal id. For the same reason the internal key is assigned **last** in the state delta: a caller key of that name displacing the real id would make `AKToolContext.fetch(...)` raise for every tool call in the run.
  - ADK's **scoped prefixes** `app:` / `user:` / `temp:` — `InMemorySessionService` merges app- and user-scoped values in on read and `temp:` is invocation-scoped, so none of them are per-session caller state. Filter on the `State.*_PREFIX` constants rather than hardcoded literals.
  - **Known and accepted** (documented, not coded around): the returned state is **accumulate-only** — ADK keeps every key written to the session for its lifetime, so a key the caller *deletes* from `framework_context` reappears on the next write-back (clear by overwriting with an empty value, not by deleting). State an agent writes itself, most commonly `LlmAgent(output_key=...)`, is indistinguishable from a tool write and round-trips too; filtering `output_key` would only catch the root agent's and leave sub-agents' behind, a less predictable rule than "the whole session-scoped state comes back".
- **LangGraph note**: this `framework_context` is distinct from the graph's own checkpointed state. LangGraph already persists its conversational state via a pickle-serializable `CheckPointer` held in `LangGraphSession` under the `"langgraph"` key (`langgraph.py:264/273`, wired at `:355`). Merged caller keys **only round-trip if the graph's state schema declares them as channels** — a prebuilt `create_react_agent` uses `AgentState` (`messages`, `remaining_steps`, `structured_response`), which silently drops unknown keys, so nothing extra comes back off `result`. Read-back is meaningful only for custom graphs whose state schema includes the caller's keys; for the prebuilt case the value is the uniform cross-framework API, not new persistence.
  - Read-back is additionally **restricted to keys the caller seeded** (`incoming ∩ result`), matching smolagents rather than ADK. *(Decision.)* A graph's result state is dominated by channels AK never put there (`messages`, `remaining_steps`, `structured_response`, and every channel a custom graph declares), so returning all of it would dump graph internals into the caller's context. Consequence: even on a custom graph, a channel the caller did not pre-seed does **not** land in `framework_context`.
- **Pydantic AI note**: `deps` is Pydantic AI's single caller-dependency slot, and **AK owns it** — today the runner calls `agent.agent.run(content, message_history=history)` with no `deps=` (`pydanticai.py:149`, `:189`), so every AK-run Pydantic AI agent already receives `deps=None`. Injecting the context dict is therefore purely additive: it cannot displace a caller-supplied value, because AK exposes no path for a caller to pass one.
  - **No runtime type check on `deps`.** `deps_type` (default `object`) is a static-typing aid; `Agent._get_deps` deliberately declines to validate at runtime, so passing a `dict` to an agent declared `deps_type=MyDeps` raises nothing at run start. A native tool doing `ctx.deps.some_field` would still fail at tool-call time — but it fails today too, against `deps=None`, so this is not a new break.
  - **Who can see it**: only tools, instruction functions, and output validators declared with a `RunContext` first parameter read `ctx.deps`. AK's own `PydanticAIToolBuilder` wraps plain callables (`Tool(func)`, `pydanticai.py:375`) and AK system tools reach state via `ToolContext.get()`, so the injected context is consumed by the **user's** native Pydantic AI tools, not by AK-attached ones.
  - **`agent.override(deps=...)` wins.** Pydantic AI resolves an active `_override_deps` ahead of the `deps=` argument, so inside an override AK's dict never reaches tools and write-back stores the unmutated copy. Not guarded against — documented as a known limitation, consistent with AK's wrap-don't-abstract stance.
  - **Traced runners need no change**: `LangFusePydanticAIRunner.run` and `OpenLLMetryPydanticAIRunner.run` delegate to `super().run(...)` (`trace/langfuse/pydanticai.py:44`, `trace/openllmetry/pydanticai.py:33`) and neither overrides `stream()`, so both inherit the injection — unlike the Langfuse LangGraph runner, which reimplements the call and has to be fixed (see "Traced runners").
- **Smolagents note (new keys don't round-trip)**: write-back reads `agent.state` after the run but **restricts it to the keys the caller seeded** — `agent.state` also holds framework-internal entries with no clean prefix to filter on, so the only safe read-back scope is "keys already present in the incoming context". Consequence: a tool that **mutates a seeded key** round-trips, but a tool that **adds a brand-new key** to the context has it **silently dropped** on smolagents (that same new key survives on OpenAI — full round-trip — and on ADK, which strips only AK-internal keys). This is a genuine cross-framework divergence: tool authors who want a context write to be portable across all frameworks must have **every key they intend to write pre-seeded by a pre-hook** (via `set_framework_context`) before the run.
  - **`additional_args` is not a private state slot — the context is shown to the model.** `MultiStepAgent.run` does `self.state.update(additional_args)` **and** appends `str(additional_args)` to the task ("You have been provided with these additional arguments…"), which is how the model learns the variable names. Two consequences, accepted and documented rather than worked around (there is no other caller-state slot in smolagents, so avoiding the append would mean dropping injection on this framework entirely): the prompt and its token cost grow with the context, and **everything in `framework_context` is visible to the model** — credentials/PII belong in a different, non-round-tripped session key on smolagents. This is also why a present-but-empty `{}` is not a pure no-op here (see Core).

### Traced runners must inherit the plumbing, not re-implement it

Every traced runner subclasses its framework runner, so it picks up injection and write-back **only if it delegates to `super()`**. Five of the six do (`trace/langfuse/{openai,adk,crewai,smolagents,pydanticai}.py`, `trace/openllmetry/*.py`) and need no change.

- **`LangFuseLangGraph.run` is the exception and must be fixed as part of this change.** It re-implements request processing, config building, `agent.agent.ainvoke(...)` and reply construction inside its span, so `framework_context` would be **silently ignored whenever Langfuse tracing is enabled** — a no-op, not an error, which is the worst failure mode for this feature.
- **Requirement: collapse the copy onto a single seam rather than duplicating the plumbing into it.** *(Decision.)* Duplicating load/inject/write-back into the traced copy would have to be repeated for every future change to the base runner — the same drift that caused this bug. Instead the traced class overrides only the one thing it needs (wiring the Langfuse callback handler into the session config the base runner builds) and its `run()` shrinks to a span wrapper around `super().run(...)`. It does **not** override `stream()`.
- **This is a behavior change to traced runs beyond adding context support**, and each difference is a fix the re-implemented copy silently lacked. Accepted deliberately, and called out here so the change is not mistaken for a pure refactor:
  - **`ToolContext` is now set** for a traced run — the copy never set it, so AK tools resolving `ToolContext.get()` did not work under Langfuse tracing.
  - **The agent's system prompt is now injected** — the copy sent only a `HumanMessage`, so a traced agent ran without its system prompt.
  - **Reply text goes through `_extract_text_content(...)`**, so list-shaped (content-block) content renders as text instead of being stringified as a list.
  - **Errors are handled by the base runner's `except Exception`**, returning the standard user-facing error reply; the span is then updated with it, where previously an exception escaped before `span.update(...)` and left the span with no input/output.
  - **Streamed traced runs now emit Langfuse traces**, because the inherited `stream()` picks up the callback handler through the same seam. Streamed runs still get no enclosing "Agent Kernel LangGraph" span — out of scope here, worth a follow-up.
- **Requirement: regression coverage** that a traced LangGraph run injects and writes back the context, so a future traced runner that re-implements the native call fails a test instead of silently dropping the feature.

### Behavior / compatibility

- Optional throughout: existing sessions and apps that never set the key are unaffected.
- Persistence: the key is a normal durable session key — persisted by `store()` and reloaded on the next turn (already covered by `Runtime.run`/`SessionStore`).
- **Accessors are additive, not a breaking change**: `Session.get`/`set`/`delete` keep working on the raw `framework_context` key, and `Session.Keys.FRAMEWORK_CONTEXT` stays public (the runners and any already-written app code that uses it keep working). The accessors become the **documented** path; the raw path is legal but unvalidated. Docs, skills, and the `*_context` CLI examples are updated to use them — the OpenAI example reads and writes the raw key (`examples/cli/openai_context/demo.py:41`, `:55`), and the ADK/LangGraph examples do the same. The examples are **already correctly scoped**: those raw-key calls sit in a pre-hook and a post-hook, while the tools use `ctx.context` (`demo.py:21`, `:30`) — only the accessor swap is needed, not a restructure.
- Pydantic AI gains context support with **no change to its public surface** — no new constructor argument, no `deps_type` requirement on user agents; an agent that ignores `deps` behaves exactly as before.
- Streaming parity: `stream()` performs the same load (before the token loop) and write-back (once, after it) as `run()` — the per-token yielding is unchanged. **Write-back happens only when the stream *completes normally*, not on every stop.** *(Decision.)* A stream can end three ways, and only one writes back:
  - **Drained normally** (all tokens yielded, loop exits) ⇒ read back the produced state and merge into the session key.
  - **Client disconnected mid-stream** (`GeneratorExit` raised at a `yield`) ⇒ **no write-back**; the previously stored context is left intact.
  - **Framework raised mid-stream** ⇒ **no write-back** (same rule as the `run()` error path above).
  - Mechanically: place the write-back **after the `async for` loop but still inside the `try`**, so a disconnect or exception unwinds before reaching it and the write-back is naturally skipped — do **not** move it into a `finally` (that would persist a partial, half-produced context). This keeps streaming atomic and consistent with `run()`: a turn's context either fully reflects a completed stream or is unchanged. Consequence to state plainly: if a user disconnects after most of a long stream, that turn's context mutations are **discarded**, not partially saved — last-known-good is preferred over partial state.
- **The read-back source differs on the streaming path** and must be specified per adapter — the streaming APIs do not all hand back a state object the way `run()` does. The read-back read itself must also sit inside the guarded region, so a failed read skips write-back rather than persisting a partial merge:
  - OpenAI: `Runner.run_streamed(..., context=ctx)` — same in-place-mutation model as `run()`, the injected `ctx` object is the source; no extra fetch.
  - Pydantic AI: `agent.agent.run_stream(..., deps=ctx)` — same in-place-mutation model as `run()`, the injected `ctx` object is the source; no extra fetch. The write-back sits immediately after the existing message-history save inside the `async with agent.agent.run_stream(...)` block (`pydanticai.py:189-195`), i.e. after the delta loop and never in the `finally`.
  - LangGraph: `astream_events` yields events, not a final `result` dict (`langgraph.py:426`); read state back via an explicit `agent.agent.aget_state(config)` after the stream completes, then merge.
  - ADK: read the ADK session `state` after the event stream drains (same source as `run()`), with `ak_tool_context` and the `app:`/`user:`/`temp:` prefixes stripped.
  - smolagents/CrewAI: no native token streaming (`stream()` raises `NotImplementedError`), so no streaming write-back applies.
- **Streaming write-back failures are logged, not raised.** *(Decision — the one place the fail-fast policy below is deliberately not applied.)* On the `run()` path a write-back error (non-picklable context, failed state read) propagates into the runner's existing `except Exception` and becomes a user-facing error reply, which is the wanted fail-fast behavior. The `stream()` paths have **no `except` of their own** (OpenAI/LangGraph/Pydantic AI use `try/finally`; ADK's `stream()` has no `try` at all) and neither does `Runtime.stream`, so the same exception would escape the generator *after the full response was already streamed* and — worse — skip `Runtime.stream`'s `store()`, losing the whole turn's session state rather than just the context. So each stream write-back (including the state read that feeds it) is wrapped in its own `try/except Exception` that **logs at ERROR with the session id and traceback and returns**: the stored context is left intact, the response the user already received is not turned into a transport error, and the session still persists. `GeneratorExit` is a `BaseException`, so disconnect semantics above are unaffected.

### Serialization

- `framework_context` must be picklable — sessions are serialized with `pickle` via `BinarySerde` (`serde.py:24/36`), so a non-picklable value would otherwise crash the whole session `store()`.
- **Policy (Decision):** fail fast. At write-back, run a targeted picklability check on the `framework_context` value alone and, on failure, raise a descriptive error naming the key and the offending type. This surfaces an actionable message during development instead of an opaque store-level pickle error, and never silently drops the context between turns. **Exception: the streaming path**, where the error is logged instead of raised for the reasons given under "Streaming write-back failures are logged, not raised" — an escaping exception there would cost the whole turn's session state.
- **Scope of the check — diagnostic, not preventive:** on frameworks where tools mutate the injected object in place (OpenAI, Pydantic AI), the non-picklable value is already present in the session before write-back runs, so the check improves the *error message* but cannot prevent the bad state from having been produced. The check runs on the merge result before `store()` either way, so the descriptive error still fires ahead of the opaque `store()` pickle failure.
- **`set_framework_context` does not pickle-check.** It validates only that the value is a `dict` — a picklability sweep on every seed would be wasted work (the caller's seed is usually trivially picklable, and a tool can insert a non-picklable value afterwards anyway). Picklability stays a write-back-time check, where it catches both cases.

## Non-goals

- Not changing how each framework stores its own internal state (the framework-name keys, and LangGraph's `CheckPointer`, stay as they are).
- Not injecting context into agent-to-agent / sub-agent calls within a workflow — hooks and this mechanism cover only the top-level run (same limitation noted in `hooks.py:15`).
- Not defining a schema/validation model for the context contents (free-form `dict`).

## Non-goals (surface)

- **No `ToolContext.framework_context` accessor.** *(Decision.)* Tools reach the context through the framework-native handle, not the session — see "Scope of the accessors" above.
- Not enforcing the hooks-only scope in code: `ToolContext.get().session` stays public, so the boundary is documented and tested-by-example, not guarded by a runtime check.
