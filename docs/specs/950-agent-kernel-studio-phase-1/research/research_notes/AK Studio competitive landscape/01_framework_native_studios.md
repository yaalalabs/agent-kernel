# Framework-vendor agent development studios and local dev UIs (state as of November 2026)

Research date: 2026-11-16. Conventions used below: "(primary)" means vendor docs, blog, changelog or repo; "(third-party)" means a review, aggregator, mirror or community post; "(snippet)" means the claim comes from a search-result excerpt and the page was not opened in full; "(pre-2026, possibly outdated)" flags sources dated before 2026.

## Product inventory: form factor, status, pricing and licensing

### Takeaway
Almost every framework vendor now ships two layers: a free local dev UI served by its CLI in the browser (`langgraph dev`, `mastra dev`, `adk web`, `devui`, `agentcore dev`) and a paid hosted control plane or no-code builder (LangSmith Studio/Fleet, CrewAI AMP Crew Studio, Mastra Platform, Agno Control Plane, AG2 Studio). Native desktop apps are being retired, not launched: LangGraph Studio Desktop was replaced by a CLI-served web UI in early 2025, and Letta deprecated its Letta Code Desktop app on 2026-10-12; OpenAI is shutting down its hosted Agent Builder canvas on 2026-11-30.

### Inferences
- The industry pattern is "CLI serves a browser UI on localhost" for dev, plus "hosted SaaS for teams and no-code". Two vendors (LangChain, Letta) have actively abandoned native desktop apps, and LangChain cited Mac-only, Docker and desktop-app friction as the reasons. AK Studio's Electron app is a contrarian form factor; it needs to justify itself with things a browser tab cannot easily do (driving local Claude Code, running local Terraform, owning the project folder).
- Hosted no-code canvases are under pressure: OpenAI is shutting its Agent Builder canvas down after about 14 months, while LangChain, CrewAI and Mastra steer no-code users to prompt-to-agent builders rather than drag-and-drop canvases.
- Pricing anchors for a future AK Studio paid tier: LangSmith Plus $39/seat/month, Agno Pro $150/month, Mastra Starter $25/month and Teams $250/team/month, CrewAI free tier capped at 50 executions/month with Enterprise by quote. The free local dev UIs (ADK web, DevUI, `mastra dev`, `langgraph dev` with a free LangSmith account) set the expectation that the local studio itself is free.

## Visual graph/canvas: read-only view of code, bidirectional editing, or no-code source of truth?

### Takeaway
The framework-native local dev UIs (LangSmith Studio, Mastra Studio, DevUI, ADK web, Foundry Agent Inspector) render a read-only graph derived from code, at most allowing prompt or config edits. The editable canvases (CrewAI Crew Studio, Agno Studio, AG2 Studio, ADK Visual Builder, AutoGen Studio, the retiring OpenAI Agent Builder) are their own source of truth (DB, YAML or JSON) with one-way code export. Only Inkeep claims true two-way sync between a canvas and hand-written code, and it relies on LLM-assisted code rewriting; nobody found offers AK Studio's "canvas as a view of real app.py/tool.py/config.yaml files".

### Cited Findings
- LangSmith Studio lists "Visualize your graph architecture"; graph mode shows "nodes traversed, intermediate states"; no statement that the graph structure is editable. [LangSmith Studio docs (primary)](https://docs.langchain.com/langsmith/studio)
- LangSmith Studio does allow editing prompts inside nodes: "Studio allows you to edit prompts used inside individual nodes, directly from the graph interface", plus a Playground for single LLM calls. [LangSmith Studio observability docs (primary)](https://docs.langchain.com/langsmith/observability-studio)
- The original desktop Studio hot-reloaded: it "detects changes to the underlying code files" so you edit code in your IDE and rerun (pre-2026). [LangChain blog (primary)](https://www.langchain.com/blog/langgraph-studio-the-first-agent-ide)
- Mastra Studio workflows: "Graph visualization with step-by-step runs" and real-time highlighting of the active step and path; the page does not say the graph is editable, though the Models panel and Agent Editor can persist model/prompt/tool changes (`editor: { model: true }`, otherwise changes last until server restart). [Mastra Studio docs (primary)](https://mastra.ai/docs/studio/overview)
- Foundry Toolkit Agent Inspector provides "real-time workflow visualization" alongside breakpoints. [Microsoft Tech Community (primary)](https://techcommunity.microsoft.com/blog/azuredevcommunityblog/microsoft-foundry-toolkit-for-vs-code-is-now-generally-available/4511831)
- ADK web has an "agent structure graph view" and a Trace tab with a per-step Graph. [ADK web docs (primary)](https://adk.dev/runtime/web-interface/); [ADK evaluate docs (primary)](https://adk.dev/evaluate/)
- ADK Visual Builder generates Agent Config `.yaml` files plus Python files for custom tools; you can edit the files directly but "some changes may not be compatible with Visual Builder"; the pencil (edit) option is "available only for agents created with Visual Builder"; some advanced ADK features are unsupported because of Agent Config limits; file writes go through local API endpoints that exist only when the web UI is served, not in `adk deploy cloud_run`. [ADK Visual Builder docs (primary)](https://adk.dev/visual-builder/)
- CrewAI Crew Studio: "The Studio project is the source of truth"; "Downloading code is a one-way export"; editing downloaded code creates a separate code-sourced automation without the visual editor. The docs page does not show a canvas; editing is conversational. [CrewAI AMP docs (primary)](https://docs-platform.crewai.com/platform/en/guides/enable-crew-studio)
- Agno Studio builds agents, teams and workflows "on a live canvas"; code-defined tools, models, DBs and schemas are registered in a `Registry`; Studio "requires db to save and load agents, teams, and workflows"; drafts vs immutable published versions with "Set Current". No export-to-code or sync-back mentioned. [Agno Studio docs (primary)](https://docs.agno.com/agent-os/studio/introduction)
- Agno marketing: "Agents you build in Studio are the same agents you'd write in the SDK, running unchanged in production" (snippet). [Agno product page (primary, snippet)](https://www.agno.com/products/control-plane)

[eesel.ai (third-party)](https://www.eesel.ai/blog/inkeep-review)

[Orangeslice (third-party vendor)](https://orangeslice.ai/blog/future-of-automation); [Braintrust (third-party vendor)](https://www.braintrust.dev/articles/best-no-code-ai-agent-builders-2026)

### Inferences
- Three distinct models exist: (1) read-only graph derived from code with hot reload (LangSmith, Mastra, ADK web, DevUI, Foundry Inspector); (2) canvas or config as source of truth with one-way code export (Crew Studio, AG2, AutoGen Studio, OpenAI Agent Builder, ADK Visual Builder via YAML, Agno via DB); (3) claimed two-way sync (Inkeep, via LLM rewriting). AK Studio's "canvas is a view of the real code files, edits flow through Claude Code with per-change accept/revert" is closest to model 3 but anchored in plain Python files, which is a defensible differentiator if round-trips are reliable.
- The ADK Visual Builder's constraint (only agents created in the builder are editable; hand edits may break it) and Crew Studio's "separate code-sourced automation" fork are the exact failure modes AK Studio's design should avoid and can cite as motivation.

### Gaps
- No primary source confirmed whether Mastra Studio's workflow graph or DevUI's workflow view is interactive beyond visualization.
- No independent test of Inkeep's two-way sync reliability was found.

## Local run, playground, step-through debugging, trace views and evaluation

### Takeaway
LangSmith Studio remains the reference for step-through debugging (interrupts, pause-after-each-step, state editing, time travel/fork) and ties directly to LangSmith datasets and experiments; ADK web has the most complete built-in local eval loop (turn a chat session into an eval case, run with thresholds); Mastra Studio adds datasets/experiments and scorers; Foundry Toolkit is the only one with true IDE breakpoints. Trace views are universal (mostly OpenTelemetry), but most dev UIs are explicitly "not for production".

### Cited Findings
- Original LangGraph Studio debugging: interrupt the agent at any time, a debug mode that "pauses after each graph step", modify an agent's response at a step and continue from there, real-time streaming of steps and tool choices (pre-2026). [LangChain blog (primary)](https://www.langchain.com/blog/langgraph-studio-the-first-agent-ide)
- Current LangSmith Studio features: run and interact, manage assistants and threads, iterate on prompts, run experiments over a dataset, manage long-term memory, "Debug agent state via time travel"; chat mode for business users requires state that extends `MessagesState`. [LangSmith Studio docs (primary)](https://docs.langchain.com/langsmith/studio)
- LangSmith Studio can "Add examples to LangSmith datasets from nodes in the thread log", run an experiment against a dataset via **Run experiment**, open a trace with **Run in Studio**, and clone a remote thread into a local agent. [LangSmith Studio observability docs (primary)](https://docs.langchain.com/langsmith/observability-studio)
- Mastra Studio: chat with model switching and sampling params; view reasoning and tool calls; annotate passages and send back as context; send follow-up messages mid-stream; run workflows step by step with custom input; run tools in isolation; view processors; browse MCP servers (built-in at `/api/mcp`); edit request context as JSON or schema form; scorers, datasets (CSV/JSON import, schemas, pinned versions) and experiments comparing 2 to 10 runs against a baseline; traces, logs, metrics. [Mastra Studio docs (primary)](https://mastra.ai/docs/studio/overview)
- ADK web: view and modify session state; Trace tab shows Event, Request, Response and Graph per step; Eval tab: "Add current session" to an eval set, edit saved cases, **Run Evaluation** with sliders for tool trajectory and response match thresholds, hover a Fail to see actual vs expected. [ADK evaluate docs (primary)](https://adk.dev/evaluate/)
- ADK eval criteria include `tool_trajectory_avg_score`, `response_match_score` (ROUGE-1), LLM-judged `final_response_match_v2`, rubric-based quality, `hallucinations_v1`, `safety_v1`, multi-turn task success, efficiency metrics, and user simulation (AI-generated user turns); the same evals run via `adk eval` CLI and via pytest using `AgentEvaluator.evaluate`. [ADK evaluate docs (primary)](https://adk.dev/evaluate/)
- DevUI: chat with file attachments, auto-generated input forms based on the first workflow executor's input type, directory-based discovery, sample gallery, OpenAI-compatible Responses API, OpenTelemetry trace view (`--tracing`), `--reload`, `--mode developer|user`, auth token enabled by default. No eval or step-through features documented. [Microsoft Learn DevUI (primary)](https://learn.microsoft.com/en-us/agent-framework/devui/)
- Foundry Toolkit Agent Inspector: breakpoints, local tracing across tool calls and agent chains; v0.30.0 notes F5 debugging with variable inspection and step-through; pytest-style evaluations in VS Code Test Explorer. [Microsoft Tech Community GA post (primary)](https://techcommunity.microsoft.com/blog/azuredevcommunityblog/microsoft-foundry-toolkit-for-vs-code-is-now-generally-available/4511831); [Feb 2026 update (primary, snippet)](https://techcommunity.microsoft.com/blog/azuredevcommunityblog/ai-toolkit-for-vs-code-february-2026-update/4493673)
- Agno Control Plane: chat with debug mode and trace inspection, version picker, tracing tree and waterfall views, human approvals that pause runs; evals not mentioned on the page. [Agno Control Plane docs (primary)](https://docs.agno.com/agent-os/control-plane); [Agno Studio docs (primary)](https://docs.agno.com/agent-os/studio/introduction)
- Letta's ADE exposed the context window and allowed editing core memory blocks live (state editing for memory-centric agents). [Letta ADE docs (primary, deprecated)](https://docs.letta.com/guides/ade/overview)
- AgentCore Agent Inspector: chat, Gantt-style span timeline, raw traces, memory search, local OTLP collector writing JSONL. [Classmethod (third-party)](https://dev.classmethod.jp/en/articles/agentcore-cli-inspector-web-ui/)
- Pydantic Logfire: datasets editable in web UI, offline experiments, online evals with judges, Gateway Playground with side-by-side model comparison and replay-script export, optimizer proposing prompts. [Logfire evals docs (primary, snippet)](https://pydantic.dev/docs/logfire/evaluate/evals/); [Gateway Playground changelog (primary, snippet)](https://pydantic.dev/changelog/gateway-playground-redesign.md)
- Crew Studio evals are delegated to Arize AX (online evals, labeling queues, experiments). [Arize blog (partner)](https://arize.com/blog/crew-studio-arize-ax-tracing-evaluation/)

### Inferences
- AK Studio Phase 1's "local run with chat, trace view and pytest test runs" is at parity with DevUI and ADK web for chat and traces, behind LangSmith Studio on step-through debugging (no interrupts, state editing or time travel in AK's Phase 1 scope), and behind ADK web and Mastra on "turn this conversation into a test case" flows. A "save this chat as a test" action mapped to AK's test framework would close the most visible gap cheaply.
- Foundry Toolkit's choice to surface evals in VS Code Test Explorer and ADK's `AgentEvaluator` in pytest validate AK's choice to run evals as pytest, not as a proprietary eval runner.
- AK's "business rules linked to code, config and tests (enforced, drafted, out of sync)" has no direct analogue in any studio reviewed; the closest are eval datasets and rubric-based criteria (ADK rubrics, Mastra scorers, Logfire judges).

### Gaps
- Current (2026) LangSmith Studio docs pages for interrupts/breakpoints and state editing were not opened; claims about those features rest on the 2024 blog plus the 2026 "time travel" bullet.
- No source documented step-through debugging in Mastra beyond step-by-step workflow runs.

## Deployment options and team features

### Takeaway
Deployment from the studio is almost always to the vendor's own hosted runtime (LangSmith Cloud, CrewAI AMP, Mastra Platform, Foundry Agent Service, Agno-connected AgentOS) or a single-cloud CLI path (`adk deploy cloud_run`, `agentcore deploy` via CDK). None of the reviewed studios offers Terraform plan/apply across AWS, Azure and GCP from the UI. Team features (RBAC, SSO, shared studios, publish/draft) are the paid hosted layer everywhere.

### Cited Findings
- LangSmith Studio: one-click deploy from local testing to LangSmith Cloud, creating a new deployment or redeploying an existing one. [LangSmith Studio docs (primary)](https://docs.langchain.com/langsmith/studio)
- LangSmith Deployment options: Cloud (US or EU), Hybrid (SaaS control plane, self-hosted data plane) and fully self-hosted in your VPC on Enterprise; Plus includes one free small serverless Agent Server; `langgraph build`/`langgraph up` use Docker. [LangChain pricing (primary)](https://www.langchain.com/pricing); [LangSmith local server docs (primary, snippet)](https://docs.langchain.com/langsmith/local-server)
- Crew Studio deploys directly to CrewAI AMP; AMP Factory can run on-prem or in private VPCs on AWS, Azure or GCP. [CrewAI AMP docs (primary)](https://docs-platform.crewai.com/platform/en/guides/enable-crew-studio); [CrewAI webinar (primary, snippet)](https://www.crewai.com/webinar/workshop-building-collaborative-ai-agents-visually-with-crewai-studio)
- Mastra: `mastra server deploy` or CI deploy on push to Mastra Platform; `mastra build` and `mastra start` produce self-contained output for your own infra; Studio deployable to a shareable URL with Studio Auth and RBAC. [Mastra Platform blog (primary)](https://mastra.ai/blog/announcing-mastra-platform)
- Mastra Agent Builder: RBAC (admin/member, IAM-style permissions), ownership and visibility, drafts until published, enterprise license for deployment. [Mastra Agent Builder blog (primary)](https://mastra.ai/blog/announcing-agent-builder)
- Foundry Toolkit: one-click deploy from local to Microsoft Foundry Agent Service. [Microsoft Tech Community (primary)](https://techcommunity.microsoft.com/blog/azuredevcommunityblog/microsoft-foundry-toolkit-for-vs-code-is-now-generally-available/4511831)
- DevUI: a "sample app" that is "**not** intended for production use"; it has no deploy feature. [Microsoft Learn DevUI (primary)](https://learn.microsoft.com/en-us/agent-framework/devui/)
- ADK: the Visual Builder codelab deploys to Cloud Run; `adk deploy cloud_run` runs headless without the builder's file-write endpoints. [ADK Visual Builder docs (primary)](https://adk.dev/visual-builder/); [Google codelab (primary, snippet)](https://codelabs.developers.google.com/codelabs/create-low-code-agent-with-ADK-visual-builder?hl=fr)
- AgentCore CLI: `agentcore deploy` builds a CDK project and synthesizes CloudFormation (AWS only). [Classmethod (third-party)](https://dev.classmethod.jp/en/articles/agentcore-cli-inspector-web-ui/)
- Agno: Studio publishes agents to a live API endpoint on your AgentOS; Control Plane offers Owner/Administrator/Member roles, email invites, custom roles on Enterprise; Pro tier limited to 1 live AgentOS and 3 seats. [Agno Control Plane docs (primary)](https://docs.agno.com/agent-os/control-plane); [Agno pricing (primary, snippet)](https://www.agno.com/pricing)
- AG2 Studio: runs inside AG2's hosted AgentOS with schedule, webhook and tool-event triggers, or export Python to self-host. [AG2 blog (primary)](https://ag2.ai/blog/studio)
- AutoGen Studio: no deploy feature; JSON export only; no built-in login. [AutoGen Studio guide (primary)](https://microsoft.github.io/autogen/0.7.1/user-guide/autogenstudio-user-guide/usage.html); [Railway (third-party)](https://railway.com/deploy/autogenstudio)
- LangSmith Fleet adds workspace vs private agents and Slack deployment; self-hosting Fleet is beta, sold through sales. [Fleet docs (primary)](https://docs.langchain.com/langsmith/fleet/index); [LangChain pricing (primary)](https://www.langchain.com/pricing)

### Inferences
- AK Studio's "deploy via locally run Terraform to one of six AWS/Azure/GCP targets, with plan/confirm/apply/destroy" is unique among framework-native studios; competitors either lock deploy to their SaaS or to one cloud (Google: Cloud Run; AWS: CDK/AgentCore; Microsoft: Foundry). This is likely AK's clearest differentiator, particularly for enterprises that want no vendor control plane.
- Leaving team features out of Phase 1 is consistent with the market, where team features are the monetized hosted layer; but every hosted competitor ships RBAC and shareable studio URLs, so AK will be compared unfavourably by teams until a later phase.

### Gaps
- Did not verify whether LangSmith Deployment or Mastra Server publish Terraform modules or IaC beyond Helm/Docker (LangSmith self-host Helm charts likely exist but were not checked).
- Google Agent Engine/Vertex deployment from `adk web` was not checked.

## AI-assisted building (prompt-to-agent, coding-agent integration)

### Takeaway
Prompt-to-agent is now standard in the hosted no-code layers (LangSmith Fleet "Build with AI", CrewAI Crew Assistant, Mastra Agent Builder, AG2 CaptainAgent, ADK Visual Builder assistant), but these generate configuration in the vendor's own store or YAML. Only Microsoft's Foundry Toolkit (via GitHub Copilot in VS Code) and Inkeep's CLI (LLM-assisted code sync) apply AI to the developer's actual source files; no studio found drives an external coding agent like Claude Code with approval cards and per-change revert.

### Cited Findings
- LangSmith Studio can "Build a no-code agent by describing it" (LangSmith Cloud only, not self-hosted): LangSmith Chat drafts name, description and instructions, then suggests connections, channels and schedules for review. - CrewAI Crew Studio: Crew Assistant asks clarifying questions and generates agents, tasks, inputs and tools; refine and regenerate. [CrewAI AMP docs (primary)](https://docs-platform.crewai.com/platform/en/guides/enable-crew-studio)
- ADK Visual Builder: AI assistant in the right panel "answers questions and can edit your agent workflow" (experimental). [ADK Visual Builder docs (primary)](https://adk.dev/visual-builder/)
- Mastra Agent Builder: natural-language builder discovers configured tools, agents and workflows from their descriptions; teammates can "vibe code" their own agents. [Mastra Agent Builder blog (primary)](https://mastra.ai/blog/announcing-agent-builder)
- AG2 Studio: CaptainAgent generates the initial graph from plain language and later extends or refactors it. [AG2 blog (primary)](https://ag2.ai/blog/studio)

### Inferences
- AK Studio's "Build with AI" (local Claude Code in the folder, approval cards, per-change accept/revert) sits in a gap between hosted prompt-to-agent builders (which never touch your repo) and IDE copilots (which have no agent-domain canvas or business-rule linkage). - Vendors use AI building mainly to recruit non-developers into their SaaS; AK's version targets developers and keeps code as the artifact, which aligns with the "source of truth must be code" view.

### Gaps
- No evidence found of any framework vendor studio integrating Claude Code, Codex or Cursor agents directly (beyond Copilot in Microsoft's case).

## Multi-framework support

### Takeaway
Every studio reviewed is tied to its own framework (LangGraph/Agent Server, CrewAI, Mastra, Agent Framework, ADK, Agno, AG2, Letta, Inkeep). Framework-agnostic coverage exists only in observability/eval layers (Logfire and `pydantic-evals`, Arize, OpenTelemetry trace viewers, Mastra's Memory Gateway), not in a build-run-deploy studio; AK Studio over 8 frameworks would be unique.

### Cited Findings
- LangSmith Studio targets "agents that implement the Agent Server API". [LangSmith Studio docs (primary)](https://docs.langchain.com/langsmith/studio)
- DevUI discovers Agent Framework agents and workflows (Python, .NET); Foundry Toolkit's AI-assisted creation names only Microsoft Agent Framework. [Microsoft Learn DevUI (primary)](https://learn.microsoft.com/en-us/agent-framework/devui/); [Microsoft Tech Community (primary)](https://techcommunity.microsoft.com/blog/azuredevcommunityblog/microsoft-foundry-toolkit-for-vs-code-is-now-generally-available/4511831)

- Agno Studio builds Agno agents/teams/workflows from an Agno `Registry`. [Agno Studio docs (primary)](https://docs.agno.com/agent-os/studio/introduction)
- AG2 Studio maps to AG2 agent configuration. [AG2 blog (primary)](https://ag2.ai/blog/studio)

- AgentCore's Agent Inspector was demonstrated only with Strands. [Classmethod (third-party)](https://dev.classmethod.jp/en/articles/agentcore-cli-inspector-web-ui/)
- Crew Studio produces CrewAI crews and flows. [Arize blog (partner)](https://arize.com/blog/crew-studio-arize-ax-tracing-evaluation/)

### Inferences
- Multi-framework is a real white space for studios, but buyers may doubt a cross-framework canvas can represent each framework's native concepts (LangGraph graphs, CrewAI flows, ADK sequential/loop agents). ### Gaps

## Developer sentiment: what is good and what is missing

### Takeaway
Sentiment evidence is thin and mostly from 2025, but consistent: developers value LangGraph Studio's visual time-travel debugging and ADK web's built-in eval loop, and complain about platform friction (Mac-only desktop app, Docker, browser/localhost quirks, login redirects), brittle reloads, missing dependencies and visual builders that break on hand-edited code or complex logic.

### Cited Findings
- The original desktop Studio was "currently available for Apple Silicon" only (pre-2026), and LangChain's CEO framed its replacement as "no more Mac-only, no more docker, no more desktop app!", i.e. the vendor itself treated those as the main pain points. [LangChain blog (primary)](https://www.langchain.com/blog/langgraph-studio-the-first-agent-ide); [X post (primary)](https://x.com/hwchase17/status/1881770525065990517)

- GitHub issue: "Langgraph Studio re-run from here fails after langgraph dev auto reload" (pre-2026 or undated). [langgraph issue #4253 (primary)](https://github.com/langchain-ai/langgraph/issues/4253)
- Studio frontend requires smith.langchain.com and a login redirect, a friction point for self-hosters and air-gapped users. [LangChain support KB (primary)](https://support.langchain.com/articles/5972390316-why-am-i-being-redirected-to-the-login-page-when-using-langgraph-studio-in-dev-mode)

[mirror of adk-python issue 4991 (third-party mirror)](https://backiee.wasmer.app/http_www_github_com/google/adk-python/issues/4991)

### Inferences
- The recurring pains (platform lock to one OS, Docker, cloud login for a local tool, network calls from a "local" app, canvas and code drifting apart) map directly onto AK Studio design choices: cross-platform Electron, no sign-in in Phase 1, local-only operation, and canvas-as-view-of-code. These are worth stating explicitly in AK Studio positioning, and the "no hidden network calls" expectation should be honoured (telemetry off by default, as ADK web does).

### Gaps
- Search summaries repeatedly mentioned third-party praise for LangGraph Studio's rewind, edit-state and fork workflow, but no specific page could be attributed, so that positive sentiment is uncited.
- Very few 2026-dated Reddit or HN threads specifically reviewing these studios were found; most sentiment evidence is from 2025 or from vendor/aggregator content. No substantive community reviews were found for Mastra Studio, DevUI, Agno Studio or Foundry Toolkit Agent Inspector.
