# Hyperscaler and model-vendor agent builder consoles and studios (state as of mid-November 2026)

Scope: OpenAI AgentKit (Agent Builder, ChatKit, Connector Registry, Evals), AWS Bedrock AgentCore (plus Bedrock Agents Classic, AgentCore console and CLI, Kiro), Google Gemini Enterprise Agent Platform (formerly Vertex AI Agent Builder / Agent Engine, plus Agent Garden and the Gemini Enterprise Agent Designer), Microsoft Foundry Agent Service and Copilot Studio, Salesforce Agentforce Builder (enterprise reference), and Anthropic's agent offerings (Claude Managed Agents, Claude Console, Claude Agent SDK). Research date: 2026-11-16.

Source conventions: "(primary)" marks vendor docs, vendor blogs or release notes. "(third-party)" marks press, blogs, community posts or vendor-adjacent writeups. "(search excerpt)" marks a fact taken from search-result text where the page itself could not be fetched (HTTP 403). Facts older than about six months are flagged as possibly outdated where it matters.

Headline finding for the report writer: the two most "pure visual builder" products in scope are being retired in favour of code-first paths. OpenAI Agent Builder and OpenAI Evals shut down on 30 November 2026 (two weeks after this research date), and the Microsoft Foundry visual workflow designer retires on 1 December 2026. AWS closed the console-configured Bedrock Agents (now "Classic") to new customers on 30 July 2026. All three vendors point users at code (an SDK or a framework) plus a config-driven managed harness, and at AI coding agents for authoring.

## Q1. Does each offer a visual canvas, can the design be exported to or round-tripped with code, and which frameworks or SDKs does it support?

### Takeaway
Only Google (Agent Studio, preview), Salesforce (Agentforce Builder Canvas view over Agent Script) and Microsoft (Foundry workflows, retiring 1 Dec 2026; Copilot Studio topic canvas) still ship a visual canvas in November 2026, and OpenAI's canvas dies on 30 Nov 2026. True two-way round-trip between canvas and text exists only in Salesforce (Canvas view and Script view over the same Agent Script) and the retiring Foundry workflow designer (visual and YAML both editable); Google and OpenAI offer one-way "get code" export. Every canvas is tied to the vendor's own framework or DSL (ADK, Agents SDK, Agent Script, Power Fx/YAML); framework openness (LangGraph, CrewAI etc.) exists only at the managed runtime layer (AgentCore Runtime, Foundry hosted agents, Google Agent Runtime), never in the canvas.

### Cited Findings

OpenAI AgentKit / Agent Builder
- Agent Builder is "a visual canvas for building multi-step agent workflows": start from templates, arrange nodes, "each connection between nodes becomes a typed edge", preview runs with live data, attach sample files and observe each node's execution (primary). ([OpenAI Agent Builder guide](https://developers.openai.com/api/docs/guides/agent-builder))
- Versioning: autosave; publishing creates "a new major version that acts as a snapshot"; API calls can be pinned to an older version (primary). ([OpenAI Agent Builder guide](https://developers.openai.com/api/docs/guides/agent-builder))
- Deployment options were (a) pass the workflow ID to a ChatKit integration (recommended) or (b) export code from the Code tab and run it yourself with the Agents SDK on your own infrastructure (primary). ([OpenAI Agent Builder guide](https://developers.openai.com/api/docs/guides/agent-builder))
- Export is one-way and lossy: Code tab, choose Agents SDK, choose TypeScript or Python; "This process does not convert your workflow graph or guarantee that every behavior transfers unchanged" (primary). ([OpenAI migration guide](https://developers.openai.com/api/docs/guides/agent-builder/migrate-from-agent-builder))
- Deprecation: Agent Builder deprecated with notice on 3 Jun 2026, shutdown 30 Nov 2026, replacement "Agents SDK or ChatGPT Workspace Agents", "ChatKit remains available" (primary). ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations))
- Also shutting down on 30 Nov 2026: the Evals dashboard, API and graders (status read-only, "Migrate to Promptfoo") and reusable prompt objects (`/v1/prompts`, "Move prompt content into your application code"). The Assistants API was shut down on 26 Aug 2026 (primary). ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations))
- The OpenAI AgentKit launch page carries the 3 Jun 2026 update that OpenAI is "winding down the Agent Builder and Evals products" (search excerpt; the page returned 403 to fetch). ([OpenAI AgentKit announcement](https://openai.com/index/introducing-agentkit/))
- AgentKit launched at DevDay on 6 Oct 2025 (third-party tracker, possibly outdated as a feature description). ([Kingy AI launch tracker](https://kingy.ai/ai-launch-tracker/agentkit-2025-10-06-new-product/))
- Third-party analysis: ChatKit and Evals reached GA while Agent Builder and Connector Registry stayed in beta; the beta visual builder was the piece cut, giving it roughly an eight-month lifespan (third-party). ([Montana Labs](https://montanalabs.ai/news/openai-s-agentkit-and-the-eight-month-lifespan-of-agent-builder/))

### Inferences
- The market has largely abandoned "visual canvas as the source of truth". OpenAI (canvas retired), Microsoft Foundry (designer retired, YAML survives), and AWS (console-configured Classic frozen) all moved to code or config files as the durable artifact. This supports AK Studio's stance that the canvas is a view over real code files, and is also a warning that a canvas alone is not a durable differentiator.
- Salesforce's Canvas view over Agent Script is the closest analogue to AK Studio's canvas-plus-Code-tab design: one text artifact, two synchronised views. Google Agent Studio and OpenAI Agent Builder are one-way exporters, which their own docs admit loses behaviour.
- No vendor canvas is multi-framework. Framework neutrality only exists at the runtime layer (AgentCore, Foundry hosted agents, Google Agent Runtime). A canvas that renders eight frameworks' code (AK Studio) has no direct hyperscaler equivalent.
- AgentCore's harness (config-defined agent with "export to Strands") is conceptually close to AK's config-driven approach, but it is AWS-hosted and Strands-based.

### Gaps
- The OpenAI AgentKit launch page and Agent Builder node reference could not be fetched (403), so the full node list (guardrail, MCP, file search, if/else, user approval nodes) is unverified here.
- Whether ChatKit workflow IDs keep working after 30 Nov 2026 is unresolved; one third-party analysis says docs do not clarify it. ([DEV Community checklist](https://dev.to/jangwook_kim_e31e7291ad98/openai-agent-builder-and-evals-winddown-migration-checklist-4no7))
- Whether the Claude Console has a form-based or visual agent editor (versus an agents list plus API) was not confirmed from a primary source.
- GA status of Google Agent Studio and the Gemini Enterprise Agent Designer is disputed across third-party reports; the Agent Studio doc still says Preview.

## Q2. What does each offer for testing (playground, evals, test datasets, simulated users), tracing and observability?

### Takeaway
Testing and evaluation is where the hyperscalers most clearly exceed AK Studio Phase 1: AWS, Google, Microsoft and Salesforce all ship managed evaluation (LLM-as-judge, test sets, multi-turn simulated users, online evaluation of live traffic, A/B tests and optimisation loops) plus OpenTelemetry-based tracing of deployed agents. OpenAI is the exception, having retired its hosted Evals in favour of the third-party Promptfoo. Anthropic offers Console session tracing and a research-preview "outcomes" self-evaluation, but no test-set product.

### Inferences
- AK Studio Phase 1's "local run with chat, trace view and test runs" overlaps with the local inspectors (AgentCore Agent Inspector, Foundry Toolkit Agent Inspector) and cloud playgrounds, but the hyperscalers go further: simulated users, online evaluation of production traffic, A/B testing and closed-loop optimisation. AK Studio explicitly excludes observing deployed systems, so this is a clear gap relative to all four big platforms.
- OpenAI's retreat to Promptfoo and Microsoft's ASSERT ("adversarial tests from policies") show two directions for linking rules to tests. ASSERT and Copilot Studio's natural-language custom metrics are the nearest analogues to AK Studio's plain-language business rules linked to tests.
- AgentCore Agent Inspector is the closest functional twin of AK Studio's local run view (local browser UI for chat, traces and memory), but it is AWS-specific and, for harness agents, requires deploying to AWS first.

### Gaps
- Public pricing for AgentCore Evaluations, Google Agent Evaluation/Simulation and Salesforce Testing Center was not gathered.
- Google Agent Simulation and Evaluation GA/preview status is not stated in the wrap-up post.

## Q3. How does deployment work (managed runtime, one-click, IaC, bring-your-own-cloud), and what are the governance features (identity, policy, guardrails, versioning, environments, approvals)?

### Takeaway
Every hyperscaler deploys to its own managed runtime (AgentCore Runtime, Google Agent Runtime, Foundry hosted agents) with one-click or CLI deploy, per-agent identity, registries, gateways and policy engines; IaC is available but vendor-flavoured (AWS CDK first with Terraform via the HashiCorp provider; Google Terraform guide; Microsoft azd). None deploys to another cloud. Anthropic is the only vendor offering a self-hostable control plane (self-hosted Managed Agents) with a choice of inference provider including Bedrock, Google Cloud and Foundry. AK Studio's "local Terraform plan/confirm/apply to one of six AWS/Azure/GCP targets with the user's own credentials" has no cross-cloud equivalent among these vendors, but each target cloud already has its own native deploy path.

### Cited Findings

- Agent Builder deployed either as a ChatKit-embedded workflow (OpenAI-hosted) or as exported Agents SDK code you run yourself (primary). ## Q6. What do developers and analysts say about strengths and limitations (lock-in, maturity, pricing)? Product snapshot of form factor, lock-in, pricing and status

Analyst and practitioner commentary centres on two themes: (1) lock-in risk from adopting a vendor platform "as a monolithic black box", with advice to keep orchestration in portable frameworks and use the cloud runtime only for production concerns; and (2) churn, evidenced by OpenAI's eight-month Agent Builder lifespan, Foundry's workflow designer retirement and the freeze of Bedrock Agents Classic. Pricing is consumption-based everywhere (vCPU/GB-hours, session-hours, credits) with tooling free. Independent developer sentiment from forums was sparse in this pass.

AK Studio can position "the canvas is just a view; your code stays in your repo" as insurance against exactly this, and the OpenAI migration guide's admission that export "does not convert your workflow graph" is a useful contrast.
- Where AK Studio Phase 1 is clearly behind: managed evaluation with simulated users and online evals, production observability, identity and policy engines, registries, team governance and A/B rollout. These are all explicitly out of Phase 1 scope and are where hyperscalers invest most heavily.
- Pricing comparisons favour AK Studio as a free tool, but all hyperscaler builders and CLIs are also free, with costs only for runtime and model usage. The cost comparison is therefore about runtime choice (AK deploys to the user's own cloud resources via Terraform) rather than studio licence.
